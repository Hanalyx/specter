### How to read these

**Workspaces the pipeline accepts: 0 of 12.**
The harness measured only crashes and extraction
diagnostics before this column existed. Extraction is not the same
property as usability, and earlier runs reported the first while the
release notes read it as the second.

**Zero crashes is not correct extraction.** A repo the adapters
understand nothing about exits 0 and emits valid JSON, scoring
identically to one handled perfectly. The assertions-per-file column and
the ZERO marker exist so that case is visible rather than averaged away.

**A zero in the struct conflicts column usually means the check did
not run.** `check` refuses structural checks while `resolve` has
errors, so every repo with a non-zero resolve rc reports zero
structural conflicts because none were looked for. Read that column
only on the rows where resolve is 0.

**Structural conflicts are the number `bugs/SP-SP-004` needs**, and
this run can supply it only for the repos that clear resolve. That
defect is P0 and its false-positive rate has only ever been measured
against the corpus the checker authors wrote themselves. Specs from
code they have never seen are the measurement that matters, and
SP-SP-060 is currently blocking it on ten of twelve repos.

**Orphan constraints are what `check` finds when it does run.**
`reverse` writes constraints that no acceptance criterion references,
and `check` treats that as an error. Both repos that cleared resolve
failed on it. The reverse compiler is producing specs its own checker
rejects, independently of the id collisions.
