## HIGH

### H1. `doctor --fix` writes files outside the workspace via attacker-controlled `settings.specs_dir`
**Pre-existing, not v0.13-introduced.** Verified.

`cmd/specter/main.go:300-332` — `discoverSpecs` sets `root = m.SpecsDir()` from a discovered `specter.yaml` and `filepath.Walk`s that path. `cmd/specter/main.go:1559-1576` — `findManifest` walks up to `/`, so a malicious `~/specter.yaml` or `/specter.yaml` is honored from any subdirectory. `runDoctorFix` calls `os.WriteFile(file, ...)` on absolute paths returned by Walk with no symlink check on the destination.

Concrete attack: a malicious repo ships a `specter.yaml` with `settings.specs_dir: /home/victim/private` (or a `..` traversal). A `*.spec.yaml` file planted at that location with `trust_level: high` triggers the rewrite predicate. Running `doctor --fix` overwrites the victim's file. Requires both the manifest and a target file under attacker influence, but plausible via malicious dependency repos.

**Fix:** validate `SpecsDir` is relative and resolves within `manifestRoot`; reject `..` segments and absolute paths.

### H2. `specter reverse` writes generated specs above `--out` via parent-walk + relative-path computation
**Pre-existing, not v0.13-introduced.**

`cmd/specter/main.go:1398-1444`, `internal/reverse/reverse.go:500-513`. The reverse command walks parent directories to find `package.json`/`go.mod` (line 1403 loop terminates only at filesystem root); on line 1441 every file path is made relative to `absTarget`. A manifest at `/package.json` becomes `../../../package.json`; `specFileName` emits `../../../<id>.spec.yaml`; `os.WriteFile(outPath, ...)` writes outside `outputDir`.

Concrete attack: run `specter reverse` from a deep subdirectory under a project where the top-level project file lives above the cwd. Generated specs land in arbitrary parent dirs.

**Fix:** after `filepath.Join(outputDir, gs.FileName)`, verify via `filepath.Rel` that the result is inside `outputDir`; reject otherwise. One-line check at line 1499.

### H3. VS Code extension: no cosign signature verification on downloaded binary
**Pre-existing.** Checksum-only trust chain.

`vscode-extension/src/binaryDiscovery.ts:304-307` does SHA-256 against `checksums.txt`, fetched from the same GitHub Releases URL as the archive (line 315). A GitHub release-token compromise (or repo-write attacker who pushes a tampered release) replaces both files together. The Specter release pipeline already publishes cosign signatures and SBOMs, but the extension never verifies them.

Concrete attack: GitHub repo or release-pipeline compromise → malicious binary + matching checksums.txt → extension installs and executes the binary as the user.

**Fix:** download `checksums.txt.sig` + cosign bundle, verify with `cosign verify-blob --bundle` (or `sigstore-js`). The signatures already exist; the extension just doesn't consume them.

### H4. VS Code extension: workspace-trust capability declared but not enforced at activation
**Pre-existing.**

`vscode-extension/package.json:34-37` declares `capabilities.untrustedWorkspaces.supported: "limited"` claiming workspace-scoped overrides are ignored. The machine-scope on settings handles that case, but no code path checks `vscode.workspace.isTrusted` before calling `downloadBinary`, `setupFolder`, or `execFile` against an untrusted workspace's manifest/spec files (`extension.ts:114` runs unconditionally).

Concrete attack: a user opens an untrusted folder containing a hostile `specter.yaml`. The extension auto-downloads the binary and runs it against the workspace — exactly what `limited` mode is supposed to prevent.

**Fix:** gate `setupFolder`, `runCoverageForFolder`, and `downloadBinary` on `vscode.workspace.isTrusted`. Allow `--version` invocations pre-trust for the walkthrough; defer everything else until trust granted.

### H5. Unreachable-annotation scanner has no per-file size cap
**v0.13-introduced (F3).**

`cmd/specter/main.go:692-700` — every test file discovered via `filepath.Walk(".")` is `os.ReadFile`d into `contents[path] = string(data)` before any scanner runs. `go/parser`, the TS regex scanner, and the Python scanner operate on the in-memory string. No equivalent of `parser.maxSpecBytes` (1 MiB) or `coverage.MaxResultsFileBytes` (16 MiB).

Concrete attack: a malicious workspace contains a 4 GiB `attack_test.go` with `1e7` empty top-level decls. `go/parser.ParseFile` allocates an AST proportional to file size; on an 8 GiB workstation, OOM is reliable. Also applies to TS/Python via `strings.Split` allocations.

**Fix:** add `MaxTestFileBytes` constant (recommend 4 MiB — tests aren't generated specs) checked in `discoverTestFiles` or at the read site in `coverageCmd`/`checkCmd`.

## MEDIUM

### M1. YAML alias / billion-laughs amplification within the size caps
**Pre-existing.**

`internal/parser/parse.go:93` (1 MiB spec cap), `internal/manifest/manifest.go:15` (64 KiB manifest cap). `yaml.v3` does not bound alias expansion at decode time. A 64 KiB manifest or 1 MiB spec with stacked aliases can expand to multi-GiB during `yaml.Unmarshal`. Size caps are necessary but not sufficient. (Note: yaml.v3 v3.0.1 fixed CVE-2022-28948 for the merge-key DoS class, but alias-loop amplification remains.)

**Fix:** decode into `yaml.Node` first, walk to enforce a node-count or depth cap before binding into typed structs.

### M2. `specter ingest` reads JUnit XML / `go test -json` without size cap
**Pre-existing.**

`cmd/specter/ingest.go:72, 88` calls `os.ReadFile(p)` with no cap. The 16 MiB cap on `.specter-results.json` does not cover ingest inputs. A malicious or accidentally large runner output (gigabytes of `system-out` in JUnit) OOMs CI.

**Fix:** apply a 16–64 MiB cap matching the results-file convention.

### M3. `specter diff coverage` baseline/current inputs have no size cap
**v0.13-introduced (C3).**

`cmd/specter/main.go:3139` reads each argument via `os.ReadFile` with no size limit, then `json.Unmarshal`. The 16 MiB results-file cap doesn't apply (read path is direct, not through `coverage.ParseResultsFile`).

**Fix:** add a `MaxCoverageReportBytes` cap (16 MiB matches convention) before `json.Unmarshal`.

### M4. `init --install-hook` symlink protection only covers `.git`, not `.git/hooks` or the hook file
**Pre-existing.**

`cmd/specter/main.go:1744-1789`. `Lstat(".git")` rejects a symlinked `.git` (verified intact for top-level), but `.git/hooks` and `hookPath` are written through `os.MkdirAll` / `os.WriteFile`, which follow symlinks. A local attacker who pre-plants `.git/hooks/pre-push` as a symlink to `~/.bashrc` between Specter's `Lstat` and the `WriteFile` gets a 0755-mode write redirected.

**Fix:** `Lstat` `hookDir` and `hookPath`; use `os.OpenFile` with `O_CREATE|O_EXCL` after explicit Lstat; refuse if intermediate components are symlinks.

### M5. TOCTOU between line-collection and write in `doctor --fix`
**v0.13-introduced (D1).**

`internal/migrate/rewrite.go:163` parses content for line numbers; `cmd/specter/main.go:2387, 2410` reads bytes and writes the rewritten bytes in two separate syscalls. Between read and write, an attacker (or another concurrent `specter doctor --fix`) could replace the file. The deletion target (line N) would now correspond to different content — potentially deleting a legitimate `id:` or `version:` key.

Realistic exploitability is low (requires existing workspace write access, and concurrent `doctor --fix` runs are unusual) but the operation is destructive in-place rewrite.

**Fix:** stat the file before write, verify mtime/size match the read; OR re-parse `result.Content` end-to-end to re-validate trust_level absence before committing.

### M6. VS Code extension: tar extraction has no path-traversal guard
**Pre-existing.**

`vscode-extension/src/binaryDiscovery.ts:273` runs `tar xzf <archive> -C <dir> specter`. The trailing `specter` arg restricts extraction to entries named `specter`, but tar honors pax/header `path` overrides that extend to `../../etc/cron.d/specter`. Symlink entries named `specter` pointing at `../../../etc/passwd` extract as symlinks without warning. Same concern for `Expand-Archive` on Windows (line 277-280).

**Fix:** pass `--no-overwrite-dir --no-same-permissions --no-same-owner` and reject symlink entries; or switch to a Node-native untar library (npm `tar` package) with strict-mode defaults.

### M7. VS Code extension: non-atomic binary install + cache-poisoning window
**Pre-existing.**

`vscode-extension/src/binaryDiscovery.ts:262-289` writes the archive to `<dir>/specter-download.tar.gz`, then extracts directly. Between the file appearing and `chmodSync(targetPath, 0o755)`, a partial binary remains at the cache path; on next launch `resolveBinaryPath` returns it. Multi-user system: another local user could race-place a malicious tar at the predictable temp path.

**Fix:** extract to a sibling temp name (`specter.partial`), `fchmod`, then `fs.renameSync` (atomic on POSIX and on same-volume Windows). Create `~/.specter/bin/` with mode `0700`; use `fs.mkdtempSync` for the extraction temp directory.

### M8. VS Code extension: no timeout / maxBuffer on CLI subprocess invocations
**Pre-existing.**

`vscode-extension/src/client.ts:200, 229` passes only `cwd` to `execFile` — no `timeout`, no `maxBuffer`. Node's default `maxBuffer` is 1 MiB. A pathological workspace or hung CLI rejects with `ERR_CHILD_PROCESS_STDIO_MAXBUFFER` (losing coverage state) or hangs indefinitely (the serialized queue blocks every subsequent call).

**Fix:** add `timeout: 60_000` and `maxBuffer: 32 * 1024 * 1024` to both `execFile` sites.

## LOW

### L1. `gitShow` regex permits ref starting with `-`
`cmd/specter/main.go:3186, 3212`. `validGitRef = ^[a-zA-Z0-9_.~^/\-]+$` allows refs like `--no-textconv` to flow into `exec.Command("git", "show", ref+":"+relPath)`. The trailing `:relPath` neutralizes most cases but is fragile.

**Fix:** add `if strings.HasPrefix(ref, "-") { reject }`.

### L2. `findManifest` walks to filesystem root
`cmd/specter/main.go:1559-1576, 1402-1429`. Walks up `filepath.Dir(dir)` until `parent == dir`. Compounds H1 by picking up misplaced `~/specter.yaml` or `/specter.yaml`.

**Fix:** stop at the nearest `.git` boundary; bound depth (32 dirs).

### L3. `go/parser.ParseFile` stack overflow on deep nesting
`internal/checker/unreachable_go.go:64`. Deeply nested `(((...)))` exhausts goroutine stack. The top-level `main.go:151` defer/recover catches and prints bug-report → exit 2. No data corruption, only DoS. Made moot by H5 (file size cap).

### L4. `json.Unmarshal` deep-nesting stack overflow on `diff coverage` inputs
Same class as L3; `encoding/json` has no depth limit. Made moot by M3 (size cap).

### L5. `specter.binaryPath` accepts any existing path
`vscode-extension/src/binaryDiscovery.ts:52-54`. User who accidentally points it at `/usr/bin/sudo` runs that. Mitigated by machine-scope; remains a footgun.

**Fix:** require regular file, refuse setuid/setgid bits, scope to user home or `/usr/local`.

### L6. VS Code extension `downloadBinary` error path leaks stack traces
`vscode-extension/src/extension.ts:424` shows raw `${e}` to user. Currently not sensitive (URL is well-known) but fragile.

## INFORMATIONAL — verified intact

The following defenses were checked and are working:

- **Go regex is RE2 (no ReDoS by construction)** — all 82 regex sites in the CLI; carefully unrolled patterns in `unreachable_ts.go:50`, `unreachable_py.go:65` are linear-time.
- **Pre-push SHA validation** — `validShaRE = ^[0-9a-f]{40}$` in `internal/manifest/prepush.go:29` blocks `--` flag injection for `git merge-base` / `git diff`.
- **GitHub Actions SHA pinning** — every `uses:` in `.github/workflows/{release,ci,pre-release-test,release-snapshot}.yml` is pinned by 40-char digest.
- **Manifest 64 KiB and results-file 16 MiB caps** — cap check happens before `yaml.Unmarshal` / `json.Unmarshal`.
- **XML decoder DTD/entity safety** — Go `encoding/xml` rejects DTD entity declarations (no billion-laughs via JUnit XML).
- **`exec.Command` argv-vs-shell** — no `sh -c`; every exec uses argv directly. Browser-open `link` is internal, not user input.
- **BETA gate TTY detection** — character-device check via `os.Stdin.Stat()` fires before stdin read.
- **VS Code extension HTTPS-only** — no plain HTTP fallback; version regex prevents URL injection.
- **VS Code execFile (not exec)** — no shell interpolation.
- **Webview CSP** — `default-src 'none'; script-src 'nonce-...'` with 16-byte `crypto.randomBytes` nonce per render; `localResourceRoots: []`; `enableCommandUris` not set; CSP invariants enforced by `csp.test.ts`.
- **Mandatory checksum verification** — no silent fallback if checksums.txt unavailable.
- **Settings machine-scoped** — `specter.binaryPath` and `specter.version` carry `scope: machine`.
- **No telemetry** — only outbound network calls are GitHub Releases API and download URL.
- **D1 `os.Exit` deferred-cleanup audit** — current code has no open file handles / temp files / locks at the os.Exit(2)/os.Exit(3) call sites, so no leaks today. Fragile if future code adds resources; recommended pattern: return typed error → `main()` translates to exit code.
- **Multi-doc YAML line numbers** — verified yaml.v3 reports absolute line across documents; `trustLevelLineSet` + `deleteSourceLines` correct.
- **`%q` formatting of unrecognized status string** — `strconv.Quote` escapes terminal control chars (ESC, BEL, CR) as literal escape sequences. No terminal injection.
- **D2 `InvalidStatuses` integer overflow** — `int` is 64-bit; results-file cap bounds the count well below overflow.

## Recommended priorities

**Before tagging v0.13.0:**

1. **H1** — workspace-scope validation on `settings.specs_dir` / `settings.exclude` / `settings.tests_glob`. Single cheap check; prevents the most serious arbitrary-write path. Pre-existing but worth closing in this cycle.
2. **H5** — `MaxTestFileBytes` cap in `discoverTestFiles` (4 MiB). The only v0.13-introduced HIGH; matches the existing size-cap pattern.
3. **M3** — `MaxCoverageReportBytes` cap on `diff coverage` inputs (16 MiB). v0.13-introduced; one-line fix.

**v0.13.1 / follow-up:**

4. **H2** — clamp reverse-generated output paths to `outputDir`. One `filepath.Rel` check.
5. **H3** — VS Code cosign verification. Largest scope (sigstore-js integration); v0.14 candidate.
6. **H4** — workspace-trust gating in extension. Mid-scope; clear fix path.
7. **M1, M2, M4, M5, M6, M7, M8** — size caps + symlink hardening + tar safety + atomic write + subprocess limits.

**Operational:**

- The `bin/specter` binary in the working tree reports `version 0.12.1`; rebuild before tagging so `--version` matches `v0.13.0`. (Not security-critical, but operationally relevant for users who copy the local binary.)

## Out-of-scope, deferred

- Deps modernization (E1/E2/E3 deferred to v0.14 per roadmap) — eslint 8→10 / TS 5→6 / jest 29→30. These don't introduce new attack surface but bring CVE-fix updates worth tracking.
