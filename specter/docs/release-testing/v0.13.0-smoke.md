## Findings

### F3 — `unreachable_annotation` is not wired into any CLI command

The function `checker.CheckUnreachableAnnotations` exists in
`internal/checker/` and is fully unit-tested, but has zero callers
in `cmd/specter/`, `internal/sync/`, or `internal/coverage/`.
End users running `specter check --test`, `specter coverage`, or
`specter sync` will never see `unreachable_annotation` diagnostics.

spec-check 1.3.0 promises the diagnostic (C-10, AC-13..AC-18); the
unit tests verify the pure function; the CLI plumbing was never
added. This makes the headline v0.13 feature dead code from the
user's perspective.

**A4 caveat:** the `@reachable manual` off-switch test (A4.1)
PASSes only trivially — there are no diagnostics to suppress in
the first place. Treat A4.1 as inconclusive until F3 is wired.

**Likely fix surface:** invoke `CheckUnreachableAnnotations` from
`coverage --strict` (or `check --test`), route the resulting
`CheckDiagnostic` entries through the existing diagnostic-printing
code path, and gate the severity by the active strictness mode
per C-10.
